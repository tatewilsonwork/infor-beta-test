# Changelog

All notable changes to `infor-beta` are documented here. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). The plugin has a single version, recorded in `.claude-plugin/marketplace.json`, `infor-beta/.claude-plugin/plugin.json`, and `pyproject.toml`. Skills carry no `version:` frontmatter (retired in 0.5.35).

## [0.5.38] — 2026-07-27

**Migration Phase I items 2–3 — Windows COM dev-path hygiene.** Dev-environment friction only; nothing here touches production (Cowork has no Excel and never enters these paths) and Phase D deletes the COM path outright. Item 1 (degrade an exhausted clipboard retry) is included since it is what made the new opt-in gate untrustworthy. **Phase I item order in `docs/migration-plan.md` is unchanged; Phase B step 3 and Phases C–H are untouched.**

**The orphan diagnosis in the plan was wrong, and the measurements are recorded here because the wrong fix is cheap to re-derive.** Every count is an `EXCEL.EXE` delta around a real render on the dev box, 2026-07-27:

- `.Quit()` was **already called at all four sites** — "add cleanup" was never the fix, as the plan itself noted.
- **Holding `wb` / `ws` / `rng` bound across `Quit()` does not orphan the process.** `CoUninitialize()` tears the apartment down and releases the proxies belonging to it, so the server exits regardless: measured **delta 0 both with and without** an explicit release, including with the raising frame's traceback deliberately retained the way a pytest report retains it for the whole session. The explicit release this release adds is therefore **ordering hygiene, not the leak fix**.
- Skipping `CoUninitialize()` entirely — the exact consequence of the unguarded `Quit()` — also measured **delta 0** on its own.
- **The actual orphan source is aborted COM *startup*.** When `CoCreateInstanceEx` fails with `-2146959355 "Server execution failed"`, the launch has already succeeded: Excel is up with ~60 threads and a full add-in set, but the interface handoff timed out, so no pointer comes back and there is nothing to `Quit()`. Reproduced twice consecutively during diagnosis, and confirmed **one orphan per failure** by instrumenting it — a full opted-in suite run printed exactly two startup failures and ended **delta 2**. All orphans on the box share one signature (0.22–0.28 GB, ~60–65 threads, 19 windows, all invisible, **no dialog**), and it matches Phase A/B's 13 (3.18 GB ÷ 13 ≈ 0.245 GB each).

**This is not fixable from inside the process** and the release is explicit about that rather than implying a cure: a graceful `Quit()` needs a pointer that was never handed back, and both alternatives are barred — force-killing trips Office crash-resiliency (the 2026-07-13 CapIQ incident) and a ROT attach would grab the analyst's own Excel and close their workbooks. So the failure is made **loud** instead of silent. It previously normalized to `RuntimeError`, the caller quietly degraded to LibreOffice, the test still passed, and the orphan was invisible — which is exactly how 13 accumulate unnoticed. **The prevention that works is item 2's gating:** a default `pytest` run now launches zero Excels.

### Added
- **`excel_to_powerpoint.excel_com_app()` — the one Excel-COM instance owner**, the same consolidation `find_soffice()` did for LibreOffice and for the same reason: four independently-maintained copies is how they diverged. It owns the apartment (`CoInitialize` / `CoUninitialize`), the `DispatchEx`, the app-level settings (`visible`, `park_offscreen`, `hide_comment_indicators`), and a **guarded** `Quit()`. All four Excel COM sites now go through it: `excel_to_powerpoint._excel_com_range_to_png`, `financial_charts._build_charts_com` / `_build_pie_com`, `workbook_aggregator._combine_via_com`.
- **A loud stderr warning on a failed Excel startup**, naming the orphan signature and stating that the instance must not be force-killed. This is what turned an invisible leak into a countable one mid-release.
- **`excel_com` pytest marker + the `INFOR_EXCEL_COM_TESTS` gate** (naming follows the existing `INFOR_SLIDE_RENDER_BACKEND` convention), registered in `pyproject.toml`'s `markers` and enforced by one `pytest_collection_modifyitems` hook in `infor-beta/scripts/tests/conftest.py` — not four copy-pasted skipifs.

### Fixed
- **The `Quit()` guard divergence.** All four Excel sites called `excel.Quit()` bare inside a `finally`, so a Quit that raises — a modal add-in dialog does exactly this — escaped and `CoUninitialize()` never ran, leaving the thread COM-initialized for the rest of the process. `slide_render.py` had guarded its Quit since it was written; these now match it. **`slide_render` keeps its `Presentations.Count == 0` check and Excel deliberately gets none:** PowerPoint's COM server is a singleton that `DispatchEx` attaches to, while Excel's `DispatchEx` creates a genuinely separate process, so `Quit` is always safe there — and a count guard would *skip* the Quit whenever a workbook failed to close, causing the very leak being fixed.
- **COM children are released in reverse creation order, inside the apartment that created them,** before the instance is quit — workbook / worksheet / range / chart at the range renderer, workbook / worksheet / chart / series at both chart builders, and the combined + source workbooks at the aggregator. Ordering hygiene rather than the leak fix (see above), and the aggregator's error path now closes an abandoned `combined` / `src` instead of leaving them to apartment teardown.
- **An exhausted clipboard retry degrades to LibreOffice instead of aborting** (Phase I item 1). `_ClipboardPasteError` stays deliberately **not** a `RuntimeError` — a transient clipboard race must not be mislabeled "Excel unavailable" — but `_render_range_to_png` now catches it explicitly alongside `RuntimeError`, with a distinct stderr note that retries were spent. Without this the opt-in gate could not be trusted to tell you whether the COM path works, since `test_pitch_deck_inserts_cap_table_into_slide7` could go red on a race rather than a defect.
- `financial_charts._build_charts_com` / `_build_pie_com` gained an `except RuntimeError: raise` pass-through so an "Excel unavailable" message is no longer double-wrapped as "chart build failed: Excel COM unavailable: …" (matching the aggregator's existing shape).

### Changed
- The four Excel-spawning tests are **skipped by default**: `test_slide_library_poc.py::test_pitch_deck_inserts_cap_table_into_slide7` / `::test_pitch_deck_inserts_ownership_into_slide` / `::test_pitch_deck_inserts_institutions_with_bloomberg` and `test_earnings_update_assembler.py::test_assemble_earnings_update_deck_inserts_cap_table_from_workbook`. Each spawns a real Excel that **must** run `Visible = True` (`CopyPicture(xlScreen)` captures what the instance renders, so an invisible one exports blank), the Cap IQ Office Tools add-in loads into it, finds its Cap IQ Pro sibling absent, and raises its own `MessageBox` — which `excel.DisplayAlerts = False` cannot suppress, because that gates Excel's alerts and not a third-party add-in's. *Accepted consequence:* the Windows COM path loses routine coverage. Phase D deletes it and nothing else depends on these tests.
- **Three neighbouring surfaces deliberately left ungated:** `test_assemble_earnings_update_deck_inserts_cap_table_via_libreoffice` (the LibreOffice variant — exactly what should keep running by default, and a test pins that it stays unmarked), `test_render_parity.py` (PowerPoint COM, already behind its own skipif), and `test_deck_contract.py` (spawns no Excel at all).

### Tests
- `test_excel_to_powerpoint.py` gains a fake COM stack so the ordering guarantees are locked **on every platform without spawning Excel** — spawning it is what leaks. Covers: `Quit` → `CoUninitialize` ordering; the apartment torn down even when `Quit` raises, when the body raises, and when no app was ever obtained; a failed startup normalized to `RuntimeError` **and** warned about; off-screen parking + `xlNoIndicator`; missing pywin32 → `RuntimeError`; and `chart_obj.Delete` → `wb.Close` → `Quit` → `CoUninitialize` order through the real `_excel_com_range_to_png`.
- **A drift lock mirroring the `find_soffice` one:** `test_no_bare_excel_dispatch_outside_the_instance_owner` scans `scripts/**/*.py` for a reappearing bare `DispatchEx("Excel.Application")`. `slide_render` is exempt by design — it dispatches *PowerPoint*, which needs the opposite handling.
- Both `_render_range_to_png` fall-throughs are pinned (exhausted clipboard retry **and** the pre-existing `RuntimeError`), plus the gate itself: env-var parsing, `pytest_collection_modifyitems` skipping marked items only, all four tests carrying the marker, and the LibreOffice variant not carrying it.

### Verification
Eight measured runs, `EXCEL.EXE` counted before and after each. **The delta equals the number of logged startup aborts, every time; zero aborts is always delta 0.** No run leaked on the render or Quit path.

| Run | Mode | Result | Startup aborts | Delta |
| --- | --- | --- | --- | --- |
| Four COM tests, **pre-fix** | opted-in | 4 passed | 0 | **0** |
| Four COM tests, post-fix (same invocation) | opted-in | 4 passed | 0 | **0** |
| Each gated test alone (4 runs) | opted-in | 1 passed ×4 | 0 | **0, 0, 0, 0** |
| `-m excel_com`, run 1 | opted-in | 4 passed | 0 | **0** |
| `-m excel_com`, run 2 | opted-in | 4 passed | 3 logged | **1** |
| Full suite ×2 | **default** | 597 passed, 6 skipped | 0 | **0, 0** |
| Full suite | opted-in | 601 passed, 2 skipped | 2 logged | **2** |

- `pytest` (default) spawns **no Excel at all** — the exit criterion is met.
- The four gated tests are delta 0 **and were delta 0 pre-fix on the identical invocation**, so that is a no-regression result, not evidence the gate cured anything.
- **The startup-abort rate is load-dependent and the orphans are self-amplifying:** the first pre-fix run, with one resident orphan, aborted zero times; by the end of the session, with 11 resident, aborts were frequent — each resident instance slows the next boot and widens the handoff timeout window. Diagnosis and verification themselves produced ~11 orphans for this reason. They release on reboot; **do not force-kill them.**
- Run 2 also surfaced `Windows fatal exception: code 0x800706b5` (`RPC_S_UNKNOWN_IF`) from faulthandler — a call into an instance whose interface had gone, the same contention symptom. It did not fail the run.
- **The exit criterion of delta 0 on a *full* opted-in run is therefore not met, and is not reachable by any change available under the stated constraints** (no force-kill, no ROT attach). Closing it needs the startup-abort window itself narrowed — see the open follow-up in `docs/migration-plan.md`.

## [0.5.37] — 2026-07-27

**Migration Phase B steps 1–2 — the visual oracle.** Adds `scripts/deck_contract.py` and `verify_deck(path) -> list[Finding]`, the machine that looks at a built deck. **Step 3 (promoting it into both assemblers as write → verify → repair → re-verify, then deleting the estimation code) is deliberately NOT in this release** — it needs analyst sign-off, so no assembler was touched and `palatino_text_width_in` / `fit_overview_textbox`'s em constants / `_set_table_height`'s row minimums / `_fill_risk_table`'s font ladder are all still in place.

Two tiers. **Deterministic and blocking:** `forbidden-string`, `unsubstituted-currency-token` / `unfilled-token`, `unfilled-placeholder` (with `expected-placeholder` advisory for the known-intentional comps / precedents / pie ones), `shape-outside-slide`, `table-taller-than-library`, and `rendered-overflow` — rendered ink below a shape's declared bottom, measured on the LibreOffice raster. **Advisory, agent-inspected, surfaced at the `deck` checkpoint:** `vision-review`, which renders every slide, extracts every embedded picture at native resolution, and returns a structured agenda (`VisionPass.targets`) for a model to adjudicate. The vision tier carries **no OCR** and pytest is not gated on it.

### Added
- **`scripts/deck_contract.py`.** `verify_deck(path, *, library, render, vision, out_dir)`; `vision_pass(...)` for the checkpoint; `Finding` carries `kind` / `severity` / zero-based `slide` / `shape` / `measured_in` / `limit_in`, so the Phase B step 3 repair loop knows how far it has to move, not merely that something is wrong.
- **The blank slide library is the geometric baseline, not zero.** Measured on the pitch fixture: against zero, 64 blocking findings, **52 of them template-inherent geometry** (36 `shape-outside-slide`, 16 `rendered-overflow`) — the library's own footnote placeholders render ~0.07" past their boxes and its tombstone slides park decorative shapes fully off-canvas, both by design. The baseline removes all 52 and leaves the 12 genuine string findings. Every geometric check now measures the deck, measures the matching library slide, and reports the **excess** — which also makes the reference self-maintaining in the Phase C sense, since an analyst who re-heights a library table moves the reference with it. String checks get no baseline: a `[x]` is a defect whether or not the library is where it came from.
- **Built slides are matched to library slides by shape-name signature** (`match_library_slide`), not by index or title text — a built deck's titles are filled, the pitch flow deletes and clones slides, and the market-entry section repeats one library entry N times.
- **`scripts/tests/fixtures/regressions/`** — one deck per historical bug, each a **real artefact** stripped to its defective slide (shape XML, layouts, masters and embedded fonts byte-for-byte original; the strip was verified not to move the measurement). Embedded fonts are deliberately kept: `rendered-overflow` is a text-layout measurement, and stripping them would make it depend on the host's installed fonts — the exact fragility Phase A identified.

### Fixed
- **A client-facing defect nobody had recorded: nine literal `[x]` cells on the contact slide.** The library's contact slide carries three spare banker blocks (`Table 13` / `Table 14` / `Table 10`, name / phone / email each) that no assembler fills, so they render `[x]` in a navy header and two body rows apiece. Present in the blank library and in **both** frozen fixtures — every deck this plugin has shipped. Reported as `unfilled-token`; if it is intentional it belongs in `EXPECTED_PLACEHOLDERS`, not in a lowered severity.
- Phase A's three `[x]` currency findings are confirmed and now caught: the ownership slide's bare `[x]` plus the comps and precedents `[x]$MM` footnotes.

### Changed
- **Phase A finding #2 reclassified — the overview cap-table picture's `#VALUE!` is expected, not a defect**, and is no longer the justification for the vision tier (`docs/migration-plan.md`, `scripts/tests/fixtures/README.md`). `E47:F48` are CapIQ UDF calls for the CY2026/CY2027 forward estimates, rows 34/35 wrap them in `IFERROR(..., "n/a ")`, and the EV/metric rows divide `$F$31` by that text — so an un-refreshed CapIQ estimate propagates `#VALUE!` into `E39:F40` by design, and CapIQ cannot be refreshed in this environment. Same for comps/precedents (array formulas ship un-evaluated) and the financial-summary LTM link (`#N/A` until the combined workbook exists). Consequently the error scan is **scoped to text shapes and table cells** and never reaches into rasterised range pictures; a blanket scan would fail every correct deck. A workbook-side scan would not help either — **zero of the 121 formula cells** on the fixture's `captable` tab carry a cached value under `data_only=True` (`=TODAY()-1` included), so it would see `None` everywhere and look green. The general claim (a string scan cannot see inside a raster) still holds; `#VALUE!` was simply the wrong example.

### Tests
- `scripts/tests/test_deck_contract.py` (19 tests). **All three historical bugs are caught, each replayed from a real artefact:** PRL17's market-entry table rendering 0.18" past a declaration of 5.710" (`rendered-overflow`; the test also asserts `table-taller-than-library` stays silent, since the declared height is *under* the library's 5.7197" — the bug does not exist in the file); PRL18's risk table declaring 5.360" against the library's 5.1715" (`table-taller-than-library`, no render needed); and the pre-v0.5.23 overview bullets rendering 2.58" past a 0.58"-tall box, with the finding required to **name** `Rectangle 15`, the LTM Revenue Breakdown band it runs into.
  - The overview case replays from **PRL14**, not PRL17: the PRL17 folder holds a post-fix re-run (`normAutofit fontScale="85000"`, box sized to the band), so the pre-fix PRL17 artefact no longer exists. PRL14 is a genuine pre-fix artefact of the identical defect one release earlier — no `normAutofit` at all, 7 bullets / 1,126 chars in a 0.58" box — as are all ten pre-v0.5.23 pitch runs on disk.
  - The two table checks are **not** redundant: either one alone catches one of the three bugs, not two.
- `test_blank_library_reports_no_geometric_findings` (the reference cannot violate itself) plus `test_library_baseline_is_non_trivial`, which fails if the baseline silently becomes all-zeros — that would pass the first test while quietly restoring the template noise the baseline exists to cancel.
- `test_frozen_fixture_findings_are_pinned` locks both fixtures' known state by finding kind, so a new finding class cannot slip in unnoticed.
- `test_error_token_scan_covers_text_and_spares_rasterised_ranges` pins the scoping decision in both directions: both fixtures stay clean, and an error value written into a text frame is still caught.

### Known limitations
- **`rendered-overflow` blind spot** (documented in the module docstring): it counts ink landing in *nobody's* declared box, which is what keeps it free of false positives, so an overflow running straight into the shape below is masked by that shape's own claim. The earnings-update fixture is the known instance — its broker table's re-grown last row renders under the summary box's text, with only 0.037" unclaimed. Pixels cannot separate the two shapes' ink inside that box, so this is not a threshold problem; closing it needs per-shape render attribution, which is step 3 territory. Mitigated by the vision tier's clearance hint (reported only when the *fill* tightened a gap the library left wider) and by such slides usually carrying another blocking finding, as this one does.
- The vision tier produces an agenda, never a verdict. A finding list with nothing blocking is not a clean bill of health on its own: `render-unavailable` and `library-unavailable` mean a whole tier did not run.

## [0.5.36] — 2026-07-27

**Phase A follow-up — one LibreOffice locator.** v0.5.35 added `excel_to_powerpoint.find_soffice()` but wired it into `slide_render` only, on the reasoning that the other five call sites were "workbook/chart paths, unaffected by this flip". That reasoning was wrong: the Windows LibreOffice MSI puts nothing on PATH, so on a dev box with LibreOffice correctly installed every one of those sites still saw "not installed" and either failed outright or silently degraded — inverting the dev/prod parity Phase A exists to create. All five now resolve through the locator.

### Fixed
- **All five remaining LibreOffice call sites resolve through `find_soffice()`** — `excel_to_powerpoint._libreoffice_range_to_png` (the cap-table / ownership range renderer), `financial_charts._libreoffice_recalc_values` / `_render_single_chart_png` / `_render_single_pie_png`, and `workbook_aggregator._recalc_with_libreoffice`. Each previously did its own `shutil.which("soffice") or shutil.which("libreoffice")`.
  - **`test_slide_library_poc.py::test_pitch_deck_inserts_cap_table_into_slide7` was failing on this** (`LibreOffice … not found on PATH`), so Phase A's "pytest green" exit criterion was not actually met: the cap-table renderer falls back from Excel COM to LibreOffice, and on a dev box whose Excel COM is unavailable the fallback could not find the installed binary. Both COM picture-insertion tests now pass through the LibreOffice path — i.e. through the same renderer production uses.
  - **Silent degradations closed:** `workbook_aggregator`'s recalc printed "not found on PATH" and returned `False`, leaving the combined workbook's cross-tab links un-evaluated on a machine that could have evaluated them; `financial_charts`' chart/pie renders degraded to "charts persisted, no deck PNGs", leaving deck placeholders in place. Both were indistinguishable from a genuinely LibreOffice-less box.
  - The messages now say "not found on PATH **or in the standard install locations**", since a PATH miss is no longer the whole story.
  - `find_soffice` is documented as the single locator (never `shutil.which` directly), with the v0.5.35 miss recorded as the reason. `financial_charts`' now-unused `import shutil` is dropped.
- Two test skip-guards did their own PATH probe (`test_excel_to_powerpoint`, `test_earnings_update_assembler`) and now use the locator. Both are `skipif win32`, so this changed nothing on Windows — but on macOS, where the installer also skips PATH, they were skipping with LibreOffice installed.

### Tests
- **A drift lock**: `test_no_bare_libreoffice_path_lookups_outside_the_locator` scans every `scripts/**/*.py` and fails if a `which("soffice"|"libreoffice")` probe reappears outside `excel_to_powerpoint.py`. This is the test that would have caught the v0.5.35 miss.
- `find_soffice` gains direct unit coverage (PATH hit wins over the install locations; a PATH miss falls back to an install location — the Windows MSI case; neither present ⇒ `None`).
- Two wiring tests pin the resolution path platform-independently — `shutil.which` stubbed to find nothing and only the locator knowing the binary, so a site that regresses to `which` cannot resolve it: `test_recalc_resolves_libreoffice_through_find_soffice` (aggregator) and `test_recalc_values_resolves_libreoffice_through_find_soffice` (charts).
- The existing "LibreOffice absent" tests patched `financial_charts.shutil.which` / `workbook_aggregator.shutil.which`, which can no longer simulate absence — `find_soffice` also probes the install locations, so a real MSI install stayed visible and the graceful-degradation assertions would have exercised the *present* path. They now patch the locator (`_no_libreoffice` / `_libreoffice_at` helpers).
- Full suite green: `561 passed, 2 skipped` (was `551 passed, 4 skipped, 2 failed` on the same tree before this change). Both previously-failing Excel-COM picture-insertion tests pass — via the LibreOffice fallback on a dev box whose Excel COM was unavailable, which is precisely the path this release repaired.
- **The 0.5.35 COM clipboard flake is unchanged and still Windows-dev-only.** This release removes one of its two failure modes — a COM *startup* failure (`Server execution failed`) raises `RuntimeError` and the documented fall-through to LibreOffice now actually finds LibreOffice. A COM failure *mid-render* is still re-raised raw by design (v0.5.21: so a mid-operation Excel error is not mistaken for "no Excel"), so whenever Excel COM is reachable-but-unhealthy the picture-insertion tests still flake — a different one each run: observed as `CopyPicture method of Range class failed` on `…inserts_cap_table_from_workbook`, and as the `Chart.Paste` `_ClipboardPasteError` on `test_pitch_deck_inserts_cap_table_into_slide7` + `test_pitch_deck_inserts_institutions_with_bloomberg`. All pass on isolated re-run (the standing remedy — never force-kill Excel; it disables the analyst's CapIQ add-ins). Whether the mid-render case should also degrade to LibreOffice, now that LibreOffice is the reference renderer everywhere, is a Phase D question and is not decided here.
- Root cause of the amplification, found while confirming the exit criterion and **not fixed here** (out of scope, and Phase D deletes the path): `_excel_com_range_to_png` leaks its Excel automation instance on every call — the COM references are still bound when `Quit()` / `CoUninitialize()` run, so the server never exits. Measured 9 → 13 resident `EXCEL.EXE` across one suite run plus probes; enough of them make `DispatchEx` itself fail. A graceful ROT-attach `Quit()` loop reclaims only a few, so the instances persist until logoff.

### Bumped
- marketplace, plugin manifest, and `pyproject.toml` versions to `0.5.36`.

## [0.5.35] — 2026-07-27

**Migration Phase A — clear the decks.** No deliverable-facing behaviour change. Three preparatory changes ahead of the architecture migration in `docs/migration-plan.md`: per-skill lock-step versioning is retired, the slide renderer is unified on LibreOffice so a production rendering bug can be reproduced on a Windows dev box, and reference artefacts from real runs are frozen as fixtures for every later phase to validate against.

### Removed
- **Per-skill lock-step versioning.** The `version:` frontmatter key is deleted from all 14 skills. The plugin version now lives in exactly three files: `.claude-plugin/marketplace.json`, `infor-beta/.claude-plugin/plugin.json`, and `pyproject.toml`. Nothing ever read the per-skill key — it cost 14 one-digit edits per release and drifted anyway (`pyproject.toml` sat 12 versions behind until v0.5.34). CLAUDE.md's "Versioning — single plugin version, all skills tied to it" convention is rewritten accordingly, the bump checklist drops its skill-frontmatter entry, and the locked-decision bullet + README + this file's header are de-staled. Done first, deliberately: every later phase produces a large diff and 14 one-digit edits do not belong inside it.

### Changed
- **LibreOffice is now the default slide renderer on every platform.** `pypdfium2` was pinned `sys_platform != 'win32'`, so Windows dev rendered through PowerPoint COM while Cowork/Linux prod rendered through LibreOffice — **a production rendering bug could not be reproduced locally.** The dependency is now unconditional and `slide_render.render_deck_to_png` prefers LibreOffice regardless of platform.
  - The PowerPoint COM backend stays reachable behind an explicit opt-in — `backend="powerpoint"`, or `INFOR_SLIDE_RENDER_BACKEND=powerpoint` for a whole session — with `BACKEND_LIBREOFFICE` / `BACKEND_POWERPOINT` / `BACKEND_ENV_VAR` exported. An unrecognised backend raises `ValueError`. Phase D deletes the COM path outright.
  - **The automatic win32 → COM fallback is deliberately gone.** A silent fallback is what produced the dev/prod divergence; a missing LibreOffice now fails loudly with an install instruction instead of quietly switching to a renderer production does not have.
- **New shared `excel_to_powerpoint.find_soffice()`** — PATH first (how prod resolves it), then the standard per-platform install locations. The Windows LibreOffice MSI never puts `soffice` on PATH, so `shutil.which("soffice")` fails on a correctly-installed dev box, which would have left the new default renderer unusable on the very machine it exists to keep honest. `slide_render` resolves through it; the five other `shutil.which("soffice")` call sites (workbook/chart paths, unaffected by this flip) are left for Phase D's backend consolidation.
- **`pillow>=10` is now a declared dependency.** It backs `pypdfium2`'s `.to_pil()` and `excel_to_powerpoint._trim_white_margins`, and was an undeclared runtime dependency of the LibreOffice path until that path became the default everywhere.

### Added
- **Golden fixtures** under `infor-beta/scripts/tests/fixtures/` — frozen reference artefacts from real analyst runs, with a README recording provenance, `sha256`, and known state. Pitch: `pitch-deck.pptx` + `pitch-workbook.xlsx` from `Project Propel Holdings (TSXPRL)` (2026-07-16, v0.5.34 — the most recent pitch run). Earnings update: `earnings-update-deck.pptx` + `earnings-update-workbook.xlsx` from `Project OTEX4` (2026-05-29, v0.5.5-era — the most recent EU run that exists; structure is still current, content is not a specification). These are reference artefacts to be *measured*, not expected outputs — nothing asserts byte-reproduction, since both deliverables embed a run date.
- **`test_render_parity.py`** — the Phase A exit criterion as a test. Renders a fixture deck through both backends and asserts they agree on rendered slide count, page aspect (vs. the deck's own aspect), normalized ink bounding box, and coarse-grid ink distribution/coverage. Tolerances are set at ~3× the measured worst case rather than guessed. Skips unless both backends are present (Windows dev only).
- `test_slide_render.py` rewritten around backend dispatch: the default is LibreOffice **even on win32** (the regression guard for this flip), COM requires explicit opt-in, the env var is honoured and case/whitespace tolerant, an explicit argument beats the env var, an unknown backend raises, and a failed LibreOffice render does **not** fall back to COM.

### Findings — recorded, deliberately not fixed here
Phase A is preparatory; each of these belongs to a later phase and is documented in the fixtures README so a checker author does not mistake them for noise.
- **A client-facing pitch deck shipped with a literal `[x]` currency token on it.** `pitch-deck.pptx` slide 9 (`Text Placeholder 4`) and slides 11–12 (`Text Placeholder 1`: `Note: All figures in [x]$MM…`). v0.5.34 added `fill_footnote_currency` and both assemblers call it, but not on every slide carrying the token. A first target for Phase B's forbidden-string scan — a contract that does not flag it is under-specified.
- **The cap-table picture on the pitch overview slide renders `#VALUE!`** in EV/Revenue and EV/Adj. EBITDA under CY2026E/CY2027E. Invisible to every string scan in the codebase, because the cap table reaches the deck as a *picture* — evidence that Phase B's deterministic checks cannot be the whole oracle, and that its vision checks over rendered PNGs are load-bearing rather than optional.

## [0.2.0] — 2026-05-15

### Added
- **`conductor` meta-skill** (`infor-beta/skills/conductor/`) — orchestrates deliverables end-to-end. Workflow: identify deliverable + codename, run deal-init if new, load the plan YAML, collect plan inputs, dispatch each stage via the `Task` (Agent) tool with file-based input / output handoff under `<deal_dir>/runs/<run-id>/stages/<id>/`, run checkpoint behaviour, emit a `summary.md`. Three reference files: `plan-schema.md`, `stage-envelope.md`, `checkpoint-behaviour.md`.
- **Plan schema** (`scripts/schemas/plan.py`) — `Plan` + `Stage` pydantic v2 models with `plan_inputs: list[InputSpec]`, `stages: list[Stage]`, three `CheckpointMode` values. Stage ids must be unique within a plan.
- **Reference resolver** (`scripts/plan_refs.py`) — pure function `resolve_refs(...)` that walks dicts/lists/strings and resolves `$plan_inputs.<name>`, `$deal.<field>` (dotted), `$stages.<id>.<name>` placeholders. Mid-string interpolation deliberately unsupported.
- **Run-log helpers** (`scripts/run_log.py`) — `make_run_id`, `create_run_dir`, `write_plan_snapshot`, `write_stage_inputs`, `read_stage_outputs`, `write_stage_log`, `write_summary`. Run-id format: `YYYY-MM-DD-<plan-id>-<short-uuid>`.
- **Deal-init helper** (`scripts/deal_init.py`) — `render_init_prompt()` (locked G7 7-field prompt), `save_deal_context()` / `load_deal_context()` / `load_or_locate_deal()` for `<deal_dir>/deal.json` persistence and directory bootstrap (`facts/`, `filings/`, `artefacts/`, `runs/`).
- **earnings-update plan** (`plans/earnings-update.yaml`) — 2-stage pilot composing `earningsupdate-infor` and `captable-infor` as sibling stages. Both stages run with `informational` checkpoint.
- **Ported `earningsupdate-infor`** from `infor-workflows` — version bumped to 0.2.0, helper paths retargeted, conductor-mode handoff block added at the top, Step 8 (companion cap table) marked as skip-when-`$STAGE_OUTPUTS`-set so the conductor composes captable as a sibling rather than the skill calling it inline.
- **Ported `captable-infor`** from `infor-workflows` — same surgical edits.
- **Plan JSON Schema** (`scripts/schemas/json/plan.schema.json`) — exported via `python -m schemas.export`.
- **`PyYAML>=6,<7`** added as runtime dependency for plan loading.
- **CLAUDE.md** "Shared helpers" snippet now includes `Plan`, `Stage`, the deal-init / run-log / plan_refs modules. Phase status table updated.

### Changed
- All shipped skill `version:` frontmatter bumped to `0.2.0` per single-version policy (E3).
- `marketplace.json` version bumped `0.1.0 → 0.2.0`.

### Notes
- v1 conductor executes stages **sequentially** in declaration order. Parallel / DAG (`depends_on`, `parallel_with`) deferred until Phase 3+ when CIM/pitch plans justify the complexity.
- Telemetry (`meta.json`: model, tokens, latency) deferred to Phase 5 per locked decision A3.
- Decomposition of `earningsupdate-infor` into `infor-wireframe` + `infor-deck-writing` + `deck-assembler` deferred to Phase 3 per locked decision H3.
